# Contributing

Useful contributions include reproducible compatibility reports, interface improvements, and carefully reviewed patch corrections.

## Report a problem

Include the application version, operating system, input page count, selected update mode, and complete error message. If a mark is misplaced, identify the physical PDF page and describe the affected entry. Avoid attaching the commercial book or an enhanced copy to a public issue.

## Work locally

Use Python 3.12 when possible:

```bash
python -m venv .venv
# Activate the environment using the command appropriate to your platform.
python -m pip install -r requirements-build.txt
python -m unittest discover -s tests -v
python -m arden_vul_enhancer
```

Synthetic fixtures are generated by the tests; the public test suite must not require a commercial PDF. End-to-end checks with an owned copy remain local.

## Keep patch data separate from source content

The distributed patch stores geometry and fingerprints, not the PDF's pages, artwork, or adventure prose. New changes should preserve this design. Bookmark labels derived from the book should be read from the owner's local copy.

Preserve the source PDF, use a separate output path, and keep failures or cancellations from leaving a misleading completed output. Highlights must have empty comment fields. A new coordinate patch needs compatibility checks against its intended source layout.

## Release checks

Run the tests, inspect representative rendered pages from an owned source copy, verify navigation destinations and highlight geometry, and build the native packages through Actions. Update the version before creating a new version tag. Attach the resulting portable ZIPs to a draft Release and review them before publication.

Keep the license, third-party notices, and corresponding utility source with distributed packages.
